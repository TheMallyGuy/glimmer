# Glimmer

Glimmer is a Roblox bootstrapper [crush](https://github.com/TheMallyGuy/crush) of successor, built with Tauri, SvelteKit (Svelte 5, runes only) and Tailwind CSS v4. Icons come from `@lucide/svelte`. Inspired from Bloxstrap, Froststrap, Fishstrap.

Tests live in `tests/`, one `<module>.test.ts` per module in `src/ts` or `src/lib`, run with `bun test`. `tests/setup.ts` (preloaded by `bunfig.toml`) replaces the Tauri plugins with in-memory fakes from `tests/helpers/` (`fakeFs`, `invoke` handlers, log spies); stub network calls by assigning `globalThis.fetch`. `.svelte.ts` rune modules can't load under Bun, so mock them with `mock.module` where a test needs them.

Rust commands live in `src-tauri/src/commands/`: `desktop/` (archive, bubble, discord_rpc, fleasion, hash, launch, mods, preps, TASX, webview_cookies, window_control...; built on Windows, macOS and Linux only) and `keyring.rs` and `log_watcher.rs` (every platform; the mobile `specta_builder()` list has `watch_latest_log` and `unwatch_latest_log`), collected automatically via `tauri-helper`'s `#[auto_collect_command]` and exported to `src/ts/bindings.ts` by `tauri-specta` in debug desktop builds. Call them as `commands.<name>()` from `$ts/bindings`. `tauri-helper` collects by function name and ignores `cfg`, so `specta_builder()` in `lib.rs` lists the commands by hand on mobile; a new command that must exist on Android goes in that list. Android: `lib.rs` splits into `base_builder()` (every platform), `desktop_builder()` (single-instance, updater, global shortcut, log watchers, the background window) and `mobile_builder()` (`tauri-plugin-shizuku`, an Android-only dependency whose `shizuku:default` permission sits in `capabilities/android.json`). Every capability file is checked on every platform build unless it has `"platforms"`, so a permission of a desktop-only plugin (`updater:default` in `capabilities/desktop.json`, the whole `overlay.json`) or an Android-only one must sit in a file limited to those platforms. Desktop-only crates (`sysinfo`, `runas`, `discord-rich-presence`, `app-finder`, updater, global shortcut) are in the desktop target table of `Cargo.toml`. The frontend must not call a `desktop/` command on Android.

Accounts: a Roblox login is a `.ROBLOSECURITY` cookie. The whole flow lives in the frontend (`AccountLogin` in `account/login.ts`, `AccountLauncher` in `account/launcher.ts`). Rust only provides `keyring_*` (the OS credential store, service `glimmer-roblox-accounts`) and `webview_cookie`, because HttpOnly cookies of the login window are invisible to JS. The cookie goes keyring only: never into state, config.json, logs or error messages. `config.json` holds just `accounts.list` (id, name, displayName) and `accounts.activeId`. Requests that need Cookie/Origin/Referer use the http plugin, which has `unsafe-headers` enabled.

Discord on Android: the Discord app binds a service, `com.discord.socialsdk.rpc.IDiscordRpcService` (exported, no permission), that takes Rich Presence SET_ACTIVITY frames as JSON strings (it sends READY first, allows 10 connections and one update per 5 s). `DiscordRpcBridge.kt` (in `gen/android`, next to MainActivity) does the raw binder transactions; `commands/discord_android.rs` calls it through JNI (`discord_android_connect`, `_send`, `_drain`, `_disconnect`; they fail with an error off Android, and are async because the bind answers on the main thread). The manifest lists `com.discord` under `<queries>`, which Android 11+ needs.

Windows: `main` (the chooser), `splash`, `settings` (the `(app)` routes), a hidden `background` window created in `src-tauri/src/lib.rs`, and the transparent `overlay` window of `tauri.conf.json`. The background window also owns the system tray icon (`AppTray`, `src/ts/tray.ts`), so the icon stays while every other window is closed. A single-instance plugin hands second launches to the existing window.

Fleasion (`integrations.fleasion.enabled`) runs Roblox with administrator rights, and Windows keeps a normal Glimmer from changing that process, reading the keys held in front of it or handing it a join. So while Fleasion is on, GlimmerBoard (the overlay shortcut) and the TASX optimizer stay off, and their rows on the Integrations page are disabled with a note. Nothing in Glimmer asks for administrator rights.

Other resources: `src-tauri/resources/` holds the bundled `Mods/`. The intlayer dictionaries live in `src/lib/translations/` (built into the frontend by the vite plugin).

## Design principles

- Minimal and dark. Keep each screen to the content and one clear action.
- Corners are 2px everywhere (`rounded-gl`). Never use larger radii or pill shapes.
- No outlines or borders around cards, rows or buttons. Separate areas with background shades and 2px gaps (`gap-0.5`).
- Sentence case for all text. No uppercase labels. The one exception is the "Inspired from Froststrap" banner, which is uppercase by design.
- Yellow (`accent`) is only for:
  - the one main action on a screen (e.g. Save and launch),
  - the selected state (tab underline, selected icon, checked switch, dropdown check),
  - notes and warnings.
- No emoji, gradient backgrounds, glows or decorative shadows. The only shadows are on floating menus and dialogs.
- Motion is short (under 300ms), ease-out and never blocks anything: entrances (tab content, rows, popups, dialogs, toasts), the sliding tab underline, press feedback and hovers. Use the animation tokens in `theme.css` (`animate-fade-in`, `animate-fade-up`, `animate-pop-in`) or Svelte transitions with `motionMs()` from `$lib/motion`. Nothing loops except the launch progress and `[danger]` text (see `RichText`), which shimmers. Always add `motion-reduce:transition-none` to transitions: `theme.css` also finishes every animation at once when the system asks for less motion.

Never hard-code a hex value when a token exists. Add new colours to `theme.css` first.

The accent tokens (`accent`, `accent-hover`, `accent-press`, `on-accent`) are user-themable: `AccentTheme` (`src/ts/theme.ts`) overrides them on `<html>` from `appState.appearance.accent`, and the values in `theme.css` are only the default yellow. Always use the tokens (never a fixed yellow) so a custom accent reaches everything. A custom accent has to be readable as text on the canvas (4.5:1).

The surface tokens (`canvas`, `surface`, `row`, ... `track`) follow the user's background colour the same way (`BackgroundTheme` in `src/ts/background.ts`), and while a background picture is set they turn slightly see-through. A window's own full-screen root uses `bg-app` (transparent over a picture); keep `bg-canvas` for things that must stay opaque, like sticky bars.

## Type

- `font-display` (Cal Sans): page titles, tab labels, primary buttons, card titles, dialog titles. Cal Sans has one weight, so always pair it with `font-normal`, and use `tracking-[0.01em]`.
- `font-sans` (Geist): all body text, descriptions and secondary buttons.
- `font-mono` (Geist Mono): Fast Flag names and values, log timestamps.

Sizes:

| Element | Style |
|---|---|
| Page title | `text-[32px]` |
| Dialog title | `text-[22px]` |
| Row title | `text-[15px] font-medium` |
| Descriptions, labels | `text-[13px] text-muted` |
| Small meta | `text-xs` |

## Sizes and spacing

- Main content area padding: `px-8 py-7`.
- Page title, then the blurb (`text-sm text-muted max-w-[520px] mb-7`), then the content.
- Setting row: `px-[18px] py-4`, stacked with `gap-0.5`.
- Control heights:

  | Control | Height |
  |---|---|
  | Small button, dropdown in a row | 36px (`h-9`) |
  | Inputs, search, toolbar buttons | 40px (`h-10`) |
  | Standard buttons | 44px (`h-11`) |
  | Tabs | 48px (`h-12`) |

- Click targets must be at least 36px. Window buttons are 44px.

## Components (lib/components)

Use these instead of writing new markup for the same job.

| Component | Use for |
|---|---|
| `Button` | Actions. Variants: `primary` (yellow, one per screen), `secondary` (tonal), `ghost` (text only: Cancel, Discard), `danger` (destructive). Sizes: `sm` / `md` / `lg`. `arrow` adds a trailing arrow for launch actions. |
| `IconButton` | Icon-only actions. `label` is required (it becomes `aria-label` and the tooltip). |
| `SplitButton` | Save and launch with a Player/Studio target menu. |
| `Switch` | On/off settings. Always pass `label`. |
| `TabBar` | Top-level sections. Lucide icon plus label, with a yellow underline and icon on the selected tab. |
| `Dropdown` | Choosing one value from a short list. |
| `SearchField` | Search and filter inputs. |
| `TextField` | Labelled text input with `error` and `hint`. |
| `TextBox` | Labelled multi-line text (`<textarea>`) with `error`, `hint`, `rows` and `mono` (Geist Mono, for pasted code). |
| `SettingRow` | Title, description, optional yellow `note`, and a control passed as the `control` snippet. Pass `href` to make it a link row. |
| `SettingGroup` | Stack of rows with an optional sentence-case label. |
| `Dialog` | Confirmations and small forms. Uses native `<dialog>`. Buttons go in the `actions` snippet: ghost Cancel first, then the action. |
| `Menu` | Context and popup menus (`MenuItem[]`), with arrow keys and focus return. |

## Writing Svelte here

- **Svelte 5 runes only:** `$props`, `$state`, `$derived`, `$effect`, `$bindable`, `$props.id()`.
  - No `export let`, no `$:`, no `<slot>`. Use snippets and `{@render}`.
  - Layouts render `{@render children()}`. Only `+layout.svelte` files get `children`.
- **Styling:**
  - Tailwind classes only, no `<style>` blocks.
  - Use `cn()` whenever a component accepts a `class` prop, so the caller's classes override the defaults.
  - For complex grid templates, use an inline `style="grid-template-columns: …"`. Arbitrary `grid-cols-[repeat(...)]` classes didn't get generated in this project.
- **Shared state:** lives in `lib/*.svelte.ts` as exported `$state` objects (`appState`, `prefs`, `installationsState`). Mutate their properties; never reassign the export.
- **Imports:** get components from `$lib`, and icons from `@lucide/svelte` at `strokeWidth={1.75}` (16px in buttons and tabs, 18px in rows).
- **i18n:**
  - Every user-visible string comes from an [intlayer](https://intlayer.org) dictionary in `src/lib/translations/<section>.content.json`. Never hard-code text, and reuse the `common` dictionary where it fits.
  - In a component, call `const sectionContent = useIntlayer("section")` from `svelte-intlayer` once at the top of the script, then read `$sectionContent.key.value`. Always use `.value` so the result is a plain string, which attributes and script code need.
  - Strings with `{name}` values are `{ "nodeType": "insertion", "insertion": "Hello {{name}}" }` entries (plain `{{name}}` strings are not detected): `$sectionContent.key({ name }).value`. Counts use an `enumeration` node whose `1` and `fallback` entries are insertions: `$sectionContent.key(n)({ count: n }).value`.
  - `bun run editor` starts the intlayer visual editor (run `bun run dev` first). `intlayer-editor@9.6.0` ships with its UI dictionaries missing and a launcher that breaks on paths with spaces, so `patches/intlayer-editor@9.6.0.patch` (applied by bun) fills the dictionaries in. Drop the patch when upstream fixes it.
  - Keys are camelCase and grouped by screen (`splash`, `choose`, `appLayout`). The generated `.intlayer/` folder is gitignored; `bun run check` and the vite plugin rebuild it.
- **Tauri:**
  - Window dragging uses `data-tauri-drag-region` on the header row and its spacer, not on an empty div.
  - Disk and process work goes through Tauri commands (`commands` from `$ts/bindings`) or the Tauri fs and store plugins. Leave a `// TODO:` naming the command rather than faking it silently.
  - Code that runs when a page loads must skip Tauri calls when `isTauri()` (from `@tauri-apps/api/core`) is false, so pages still render in a plain browser and the intlayer editor.
  - Never build an app path by hand (`appDataDir()`, `join(...,"mods")`). Add a method to `PathManager` and call that, so locations can be moved from one place.
  - App config is persisted through `Configuration` (`config.json`). Don't create another store for it.

## Accessibility (required)

- Use real `<button>`, `<a href>`, `<input>` + `<label>` elements. Never put a click handler on a div.
- Icon-only buttons need a label. Switches need `label`, or a visible label that points at them.
- The yellow focus ring comes from `theme.css`. Don't remove outlines without replacing them.
- Tabs, dropdowns and menus support arrow keys, Home/End, Enter and Escape. Keep that working when you change them.
- Text contrast must be at least 4.5:1. `text-muted` on `bg-row` is the lowest allowed pairing for body text.
- Pair drag-to-reorder with a keyboard option (the handle plus arrow keys) and announce the change in a live region.

## Copy

- Plain verbs and sentence case. Buttons say what happens: "Save and launch", "Delete mod", "Install".
- An action keeps the same name through the whole flow: Install, then Installing…, then Installed.
- Errors say what went wrong and how to fix it. They don't apologise.
- Empty states tell the person what to do next and offer the button to do it.
- Use placeholders like `[version hash]` for real data we don't have yet. Never invent numbers.

## Don'ts

- No borders or outlines as decoration, no rounded-lg or pills, no uppercase headings.
- No second yellow button on a screen.
- No new colours, fonts or radii outside `theme.css`.
- No emoji or decorative gradients (Froststrap's own thumbnail gradients are data, which is fine).
- Don't warp or restyle the Glimmer or Froststrap logos. Use `static/froststrap.png` as it is. For Glimmer use the `GlimmerLogo` component (the shapes of `glimmer-logo.svg`, drawn inline); its mark follows the accent colour and nothing else about it changes.

## Before finishing a change

1. It uses tokens and existing components.
2. It works with the keyboard, and the focus ring is visible.
3. It has no `<style>` blocks and no Svelte 4 syntax.
4. `bun run check` passes.
5. `bun test` passes, and new logic in `src/ts` or `src/lib` has a test file in `tests/`.
